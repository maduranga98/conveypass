# Permissions matrix

The single source of truth is the `PERMISSIONS` table in `src/lib/permissions.ts`. Cloud Functions deploy from their own folder, so a mirror lives in `functions/src/permissions.ts`; `src/lib/permissions.test.ts` fails if the two differ. Route guards (`rolesFor('area.<role>')`) and `createUser` (`canCreateRole`) read this table. Firestore and Storage rules cannot import it, so they are written to agree with it and are covered by the rules tests.

UI guards are a convenience. Firestore rules and the Cloud Functions enforce access, always scoped to the caller's tenant (called "company" in the UI).

## Roles

| Role | Claim `role` | Sign-in | Scope |
|---|---|---|---|
| Super admin | `platform` (+ `platformAdmin`) | Email + password at `/platform/login` | Platform only, no tenant. Created by script (`npm run superadmin:create`). |
| Company Admin | `admin` | Email + password | Own company. A company can have several. |
| Officer (approvals) | `officer` | Email + password | Own company. |
| Supervisor | `supervisor` | Email + password | Own company and contractor. |
| Safety Officer | `safety` | Email + password | Own company, not tied to a contractor. |
| Security | `security` | 8-digit PIN | Own company. |
| Driver | `driver` | 8-digit PIN | Own company and contractor. |

PINs are 8 digits, generated by the server, stored only as an HMAC (`pinIndex`) and shown once. See the PIN section of `CLAUDE.md`.

## Areas (route guards)

| Area | Who may open it |
|---|---|
| `/platform` | Super admin |
| `/admin` | Admin |
| `/officer` | Officer |
| `/supervisor` | Supervisor |
| `/safety` | Safety Officer |
| `/security` | Security |
| `/driver` | Driver |

Anyone else gets the 403 page; a signed-out visitor goes to the matching sign-in screen.

## Later modules

The Safety Officer shell is an empty dashboard. Inspections, violations, penalties and suspensions (and the Supervisor's after-the-fact verification), vehicle types, penalty types, compliance document rules and the Supervisor's trip assignment are not built. When they are, add their actions to `PERMISSIONS` (both copies) and this document, instead of adding role checks elsewhere.
